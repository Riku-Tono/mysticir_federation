# MysticIR Federation v0.8.5

> **表面が違っても、地下パイプラインは同じ**

異なる記法を持つ2つの言語 — **💩 ScatLang** と **🌊 SeaIR** — が同一の Core AST に正規化され、そこから同じ CEK トレースをたどり、代表的な失敗ケースにおいて同じエラーシグネチャに到達することを確認するプロトタイプ検証デモです。

---

## 概要

MysticIR Federation v0.8.5 は完全な形式的証明ではありません。代表的な3つの失敗ケースを対象とした**プロトタイプ検証デモ**です。主張の核心は次のとおりです：

> 表面の記号が異なっていても、プログラムが Core AST に変換された時点で両者は区別不可能になります — 同じ CEK マシンを経由して、同じステップで同じエラーが発生します。

現在の実装は ScatLang と SeaIR 両方のトークンを受け付け、同一の Core AST ノードにマッピングする**共有正規化パーサ**を採用しています。v0.8.5 において「2つの独立したフロントエンドが収束する」と表現するのは過大評価であることに注意してください。

---

## 2つの表面言語

以下のプログラムはどちらも同じ意味を持ちます：

| | **💩 ScatLang** | **🌊 SeaIR** |
|---|---|---|
| ゼロ | `💩₀` | `🌊` |
| N | `💩×N` | `🌊×N` |
| mod | `⊛` | `⚫` |
| 代入 | `←` | `⚓` |
| フラッシュ | `🚽⇐` | `🏝️` |
| while | `⟳` | `🌀` |
| succ | `💩⁺(…)` | `〰️…` |

記号は異なりますが、どちらもパーサ層で同一の Core AST ノードに正規化されます。

---

## パイプライン構造

```
💩 ScatLang（表面パーサ）        🌊 SeaIR（表面パーサ）
          │                               │
          └───────────────┬───────────────┘
                          ▼
                      Core AST
                   （同一のツリー構造）
                          │
                          ▼
              CEK マシン / トレース
            （同一ステップ列、同一継続）
                          │
                          ▼
                  Error Federation
             （同一エラーシグネチャ、
               フロントエンドラベルを除く）
```

`💩ScatLang` / `🌊SeaIR` のフロントエンドラベルはトレース記録に保持されるため、**表面の違いは証拠として残りつつ**、内部の実行は同一となります。

---

## 検証結果

3つの代表的な失敗ケース全てで `ast_equal`、`trace_equal`、`error_equal = true` かつ `surface_diff = true` を確認しました。

| ケース | エラー種別 | ast_equal | trace_equal | error_equal | surface_diff | ステップ数 |
|---|---|---|---|---|---|---|
| mod by zero（ゼロ除算） | `ScatError` | ✅ | ✅ | ✅ | ✅ | 12 == 12 |
| unbound variable（未束縛変数） | `ScatError` | ✅ | ✅ | ✅ | ✅ | 2 == 2 |
| step limit / infinite loop（無限ループ） | `StepLimitError` | ✅ | ✅ | ✅ | ✅ | 40 == 40 |

ステップ数が一致するのは、両方の表面記法が同一の Core AST に正規化されるため、CEK マシンが同じステップ数だけ進むからです。

---

## 4つの検証指標

**`ast_equal`** — パース後に `parse(scat_src) == parse(sea_src)` を構造的同等性で比較します。`true` は実行開始前に両記法が同一の内部ツリーを生成することを意味します。

**`trace_equal`** — CEK マシンが生成したステップ列記録をフロントエンドラベルを除いて比較します。`true` は両者が同一の実行パスをたどったことを示します。

**`error_equal`** — エラー発生時点の状態フィンガープリントをフロントエンドラベルを除いて比較します。`true` は同一ポイントで同一シグネチャの失敗が発生したことの証拠です。

> ⚠️ 現在のシグネチャには `error_message` のテキストが含まれています。将来のバージョンでは、文言変更による脆弱性を避けるため、安定した `error_code` と人間可読メッセージを分離することが望まれます。

**`surface_diff`** — フロントエンドラベルを**含めた**状態で比較した場合、不一致が期待されます。`true` は表面の違いが記録に保持されていることを意味します。

4つの指標全てが `true` の場合、そのケースにおける Federation の主張 **「表面が違っても、地下パイプラインは同じ」** が確認されたことになります。

---

## なぜ 💩 であって A ではないのか？

`💩` と `🌊` は**表面マーカー**であり、意味論的なプリミティブではありません。MysticIR で重要なのはどの記号が使われるかではなく、その記号が同一の Core AST ノードに投影されるかどうかです。`A`、`B`、その他どんな記号でも同様に機能します。地下パイプラインは表面記法に無関心です。

---

## アンダーフローについて

`pred(💩₀)` は MysticIR においてエラーを発生させ**ません**。実行を停止させるのではなく、`Underflow` 値（`💩∅`）を返し、値として静かに伝播します。アンダーフローは v0.8.5 の Error Federation ケースから意図的に除外されています — エラーイベントではなく**値**として扱われます。

## 使い方

**動作環境:** Python 3.10+

```bash
python mysticir_federation_v085.py
```

出力: 同じディレクトリに `mysticir_v085_error_federation_report.json` が生成されます。

**プレゼンテーションデモ:** `demo.html` をブラウザで開くと、パイプライン構造と検証結果をインタラクティブに確認できます。
